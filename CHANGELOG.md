## 2.0.0-dev.4

- `memory_guard` user define: builds libzt with a guarded allocator for finding heap corruption. Each
  of libzt's allocations (lwIP's packet buffers included: it allocates them with `malloc`) gets its own
  pages ending at a guard page, and freed memory stays inaccessible for the next 4096 frees, so an
  overrun, a write after free or a double free inside libzt faults at once, in libzt, instead of
  damaging the app's heap. libzt keeps its symbols then, so a crash names the function.
  `ZeroTierMemoryGuard.stats()` reports what it holds (null without the guard). About 8 µs per
  allocation; off by default.

## 2.0.0-dev.3

- Fix: a crash when joining networks right after `start()` (libzt says the service runs before it has
  created its node; the join dereferenced a null pointer). `start()` now completes once the node has
  an id, and joins made while it starts are held until then.
- Fix: network names were never returned (`zts_net_get_name` accepts only its exact maximum length).

## 2.0.0-dev.2

- `ZeroTierNode.start()` and `stop()` return futures: libzt stops its service on another thread, and
  starting again before it finished crashed. The storage path is applied again on every start.
- Fix: cancelling a `watch()` subscription hung until the state changed (so code awaiting the cancel
  before `stop()` never stopped the node). `waitUntilReady` no longer keeps polling after a timeout.

## 2.0.0-dev.1

- Pure Dart package with a native-assets build hook that compiles libzt 1.8.10 from source (no prebuilt
  binaries; 16 KB page alignment on Android; works with `dart test` on the desktop).
- `@Native` bindings generated by ffigen 23.
- New: `ZeroTierDatagramSocket` (UDP), `ZeroTierServerSocket` (TCP server), `ZeroTierNode.watch()` and
  `waitUntilReady()`, network status, names and IPv6 addresses.
- One shared adaptive poller for all sockets.
- Breaking: the 1.x result types and `waitFor*` helpers are replaced by exceptions and `watch()`.
